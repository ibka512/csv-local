CSV 中文乱码，
先分清是哪一种。

CSV 是文本文件。文件保存时的编码与打开软件猜测的编码不同，中文就可能显示错误。先保留原文件副本，不要把乱码直接保存回去。

1. 编辑器里中文正常，Excel 双击后乱码

如果原文件是 UTF-8，可导出为 UTF-8 BOM。BOM 是文件开头的编码标记，微软说明带有它的 UTF-8 CSV 可以正常打开。也可在 Excel 的「数据 → 获取数据 → 从文本/CSV」导入，并指定 UTF-8。

依据：Microsoft Support — Opening CSV UTF-8 files correctly in Excel

2. 自动读取失败，旧系统导出的文件

简体中文旧系统常见 GBK / GB18030；繁体中文文件可能为 Big5。打开本地转换工具，选择原始编码并核对真实姓名、城市等文字，再导出 UTF-8 BOM。猜测编码没有通用保证；能解码也不代表选对了。

3. 中文正常，但整行挤在一个格子

这是分隔符问题。文件可能使用逗号、制表符或分号。在 Excel 导入界面选择实际分隔符。工具里的「预览分隔符」只调整显示，导出不会重写文件结构。

4. 手机号变科学计数法，编号丢了前导零

这是 Excel 的类型推断，添加 BOM 无法解决。通过「数据 → 从文本/CSV」导入，将相关列指定为文本。如果数据已经被 Excel 保存并截断，应重新取得原始导出文件。

5. 文件里已经出现问号或替换字符 �

如果错误字符已经写进文件，仅切换编码通常无法恢复。向数据来源重新导出原文，或使用未覆盖的备份。本工具不会声称可恢复已经丢失的文字。

本地处理与使用边界

在线工具不上传文件，不加载分析脚本，所有转换在浏览器内完成。托管平台会收到网页访问请求；点击 GitHub 或爱发电链接会进入对应平台。可下载离线压缩包，解压后打开 index.html，断网使用。

只处理可信文件：CSV 中的公式可能在表格软件里执行。本工具不执行公式，也不清理公式；导出保留原有文本。文件上限 5 MiB；支持现代 Chrome、Edge、Firefox、Safari 中的 TextDecoder / TextEncoder。
